# 服主运行配置

**在服务器安装目录执行以下命令**。命令只修改本机私有配置，不需要网页账号或开放管理端口。

## 每房 AI 数量上限

例如限制每个房间最多 5 名 AI：

```bash
node tools/server-settings.mjs ai-limit 5
```

数值范围为 `0–19`，`0` 禁止添加 AI。房间总席位限制仍正常生效；真人与观战者不计入 AI 数量。

查看当前配置、恢复不额外限制：

```bash
node tools/server-settings.mjs show
node tools/server-settings.mjs ai-limit unlimited
```

- 运行中的服务器约 **1 秒**内应用命令，无需重启。等待室同步显示上限。
- 下调时，等候房从最后一个席位开始自动移除多余 AI，保留真人及前面的 AI；进行中的对局不更改成员，结束回到等候房后再应用新上限。
- 上限限制新增 AI 及开局，不改变房间容量、真人加入、观战或断线续玩。提高上限不会自动补回已移除的 AI。
- 配置保存到 `runtime/server-settings.json`，服务器重启后仍有效。没有配置时默认不限，分发包不包含本机配置。
- CLI 显示的是文件/环境配置，不代表另一个目录下的服务器已读到它；多实例部署必须使用对应实例的配置目录。

## 配置目录与启动默认值

服务器与 CLI 都可通过 `SP_SERVER_SETTINGS_DIR` 指定目录。相对路径以安装目录为基准，CLI 的 `--dir` 优先于环境变量：

```bash
node tools/server-settings.mjs ai-limit 5 --dir runtime/server-a
node tools/server-settings.mjs show --json --dir runtime/server-a
```

启动服务器时也应设置 `SP_SERVER_SETTINGS_DIR=runtime/server-a`。可以使用 `SP_MAX_AI_PER_ROOM=5` 指定**启动默认值**，有效持久配置优先于此变量；`unlimited` 表示不限。`历史缓存相关环境设置已停用。

请备份私有配置目录，不将其放在 `public` 或提交 Git。首次启动遇到损坏的配置文件会报错；运行中损坏文件会记录警告并继续使用最近有效值。删除配置文件会恢复本次启动时的环境默认值，未设置时恢复 AI 不限、预缓存允许。

配置仍为 version 1；旧文件仅含 `maxAiPerRoom` 时，预缓存要求按 `false` 读取。CLI 修改一个字段保留另一个；同一目录的命令应依次执行，原子替换仍以最后写入为准。损坏文件拒绝部分字段修改，避免更新 AI 上限时误清除严格模式；可备份后修复 JSON，明确保留两个设置。

## 素材缓存管理

采用上游素材包导入与缓存，见 [当前说明](ASSET_CACHE.md)。旧严格准入、在线补齐及其限速已停用；历史配置可读取但不再参与入场。asset-cache、asset-cache-limit 命令会明确报停用。

## 房间目录与转让

房间列表是实时内存房间，不是历史记录。所有未离开的真人都掉线时标为「断线保留」并置底，仍计入总房间和进行中统计；房主离线但其他真人在线时只标「房主离线」。进行中的独立模拟默认在最后一次断线后保留 **2 小时**供原玩家续玩；超期后由清理扫描移除身份与房间，普通扫描最长间隔 15 秒。同盟对局仍为 10 分钟，等候房断线席位仍为 60 秒；真正结算后房间回到等候状态，断线席位重新使用 60 秒期限，在线成员可以重开，最后真人离开后释放。已有调用方显式窗口覆盖与带宽紧急保护期间暂缓超期清理的规则保留，见 [D033](development/DECISIONS.md#d033)。

等待室房主可点击在线真人成员卡上的皇冠按钮并确认转让。新房主交换到 P1，其他准备与个人配置保留，旧房主仍需满足普通成员的准备要求。AI、观战和离线成员不能接收转让。对局中不移动座位；因退出发生的自动移交在回到等待室时将当前房主归 P1，避免改变本局固定卡池分组。
