# 素材缓存：采用上游方案

从本 fork 合并 0.3.1 起，按用户 2026-10-18 的决定采用作者的素材包导入与缓存实现，减少后续同步差异。二十人房间、分组卡池及轮选不变。

标题画面可使用「下载完整素材」或「导入素材包」。已有素材可从文件夹、素材 ZIP 或完整包 ZIP 导入，浏览器对照服务器清单验证 SHA-256。需要 HTTPS 或 localhost；缓存按访问地址隔离。后台仅注册上游 /sw.js，只处理同源带内容哈希的素材，未命中时走网络。

具体操作、限制和打包入口见 [部署指南](DEPLOY.md#25-玩家导入已有素材需要-https)。游戏设置中的素材缓存管理也沿用上游。

旧多人版的目录同步、增量在线补齐、严格缓存准入和补齐专用限速均已停用。旧的 asset-cache、asset-cache-limit 服主命令现在明确报停用；旧私有配置字段可以读取以兼容历史文件，但不再影响入场或网络请求。无需完整导入缓存即可加入房间。

旧 /asset-cache-sw.js 根作用域注册会在新页面启动时被同作用域的上游 /sw.js 替换；旧缓存数据不会自动转换或作为新版导入缓存使用。已有玩家如需复用素材，应在新版界面重新导入现有素材包。服务器仍需重启才能加载本次代码更新。

旧版本实现与验证保留在开发历史中，源码链接固定到退役前的提交；这些记录不代表当前功能。
